Research reviewed on 2026-11-19. The compositions below are original applications of techniques documented in the linked sources. Build each presentation with its existing content, native HTML controls, procedural graphics and bundled font files for offline use.

## Patterns to adapt

1. **Live procedural backgrounds.** Put Canvas 2D in an absolutely positioned, pointer-transparent hero layer marked `aria-hidden`. Give Agiel sparse pulse trains and engraved ticks, Confessor intersecting wavefronts that stay dim under the reading column, and Seeker flowing contour bands with one slow directional glint. Use a stable seeded field, limit drawing to the visible hero and cap backing resolution. Hold graphics behind a stable scrim. Paint a static frame for reduced motion, stop drawing while the hero is offscreen or the tab is hidden, and expose a visible pause control for ongoing motion. If canvas is unavailable, render the static CSS ground. [Three.js procedural graphics examples](https://threejs.org/examples/) · [tsParticles canvas-background documentation](https://github.com/tsparticles/tsparticles/blob/main/websites/website/docs/guide/bundles-particles.md) · [W3C pause, stop, hide](https://www.w3.org/WAI/WCAG22/Understanding/pause-stop-hide.html) · [Motion reduced-motion documentation](https://motion.dev/docs/react-use-reduced-motion)
2. **Split hero with a meaningful instrument panel.** Use the dominant column for title, abstract and section entry. Make the smaller panel communicate study structure with actual content such as construct labels or topic waypoints. Keep decorative waveform values visually distinct from sourced measurements. Use content-driven hero padding and stack the second column after the main copy on small screens. Local HTML God reference `sensei-landing-hero/references/backgrounds-and-heroes.md`.
3. **Reading progress and waypoints.** Use a thin progress line attached to the contents bar, with ordinary section links usable before JavaScript loads. Give the active section a visible text/shape cue. Use scroll-driven animation as an enhancement for the progress line while keeping the text and navigation available at every scroll position. Where the bar is sticky, use `scroll-margin-block-start` on anchor targets so headings clear it. [Chrome scroll-driven animation guide](https://developer.chrome.com/docs/css-ui/scroll-driven-animations)
4. **Evidence as a composed panel.** For Agiel, use a specimen card with named claims and links to the corresponding source. For Confessor, group a passage, its interpretation and its citation together in consecutive reading order. For Seeker, link route waypoints to the corresponding study sections and keep annotations beside the map or below it on small screens. Size panels by importance and reading space. Local HTML God reference `sensei-landing-hero/SKILL.md`, layout and proof sections.
5. **Citation margin and compact disclosure.** Use short citation links at the claim and native `details` for longer annotations. Confessor can place secondary notes beside the reading column at generous widths, then let them follow the relevant passage in source order when space runs short. Put references, summary controls and chart data in the keyboard order. [WHATWG details element](https://html.spec.whatwg.org/multipage/interactive-elements.html#the-details-element)
6. **Container-driven reflow.** Give wide reading columns `minmax(0, 1fr)`, children `min-inline-size: 0`, long URLs `overflow-wrap: anywhere` and flexible rows. Stack evidence and annotation panels when their own container tightens. Confine genuine two-dimensional tables and plots to their own labeled scroll regions. Check 320px reflow, long titles, expanded disclosures and the header at browser zoom. [CSSWG container queries](https://www.w3.org/TR/css-contain-3/#container-queries) · [W3C reflow](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html)
7. **Readable sectional pacing.** Alternate full-width study passages with locally bounded visual panels. Use a single quiet reveal on decorative frames where it improves orientation. Leave content rendered in its final state when reduced motion applies and ensure that print retains every study passage. Local HTML God references `sensei-landing-hero/SKILL.md` and `sensei-motion-ui/SKILL.md`. [Chrome scrollytelling guidance](https://developer.chrome.com/docs/modern-web-guidance/guides/ui-behaviors/scrollytelling)

Treat the linked sites and repositories as research provenance. The deck HTML should load any artwork and typography locally and request no runtime resources from the web.

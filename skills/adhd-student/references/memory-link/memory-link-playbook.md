# Memory Link playbook

A **Memory Link** is a small, deliberate bridge between something the student must remember (a typology, a taxonomy, a list, a heavy definition, a process, a number) and something the student already knows or can easily picture. Each Memory Link has up to four parts:

1. **Item**: exactly what must be remembered, in the source's own words and order.
2. **Code**: the compact retrieval cue (acronym, acrostic, image, story, peg, rhyme, place, analogy).
3. **Simple version**: the heavy definition rewritten in plain, concrete words (about 15 to 25 words, one idea).
4. **Everyday anchor**: a link to prior knowledge (a place, routine, game, food, person, app) that the student actually has.

Evidence for each technique is in `technique-evidence.md`. Worked examples are in `applied-linguistics-examples.md`.

Core principle: a Memory Link is a retrieval handle, not the understanding. Understand first (even roughly), then attach the handle, then test recall without looking. Use mnemonics for facts that must be recalled (names, order, labels, criteria). Use explanation, analogy and self-explanation for ideas that must be understood.

## 1. Decision table: which technique for which item

| Item type | First choice | Backup | Why / notes |
|---|---|---|---|
| Ordered list, 3 to 7 items (steps, stages, ranks) | Story/link method (chain the items in a short vivid story) | Acrostic sentence; rhyme | Story chaining strongly supports order recall (Bower & Clark, 1969). Keep the story to one scene. |
| Ordered list, 8 to 20 items | Method of loci (walk a familiar route) or peg list | Chunk into 3 to 4 groups, then story per group | Pre-learned frameworks (loci, pegs) preserve order best (Roediger, 1980). |
| Unordered set, 3 to 7 items (components, criteria) | Acronym or word-like code (from first letters) | Single composite image | Acronyms cue retrieval of item labels but not meaning. Add the simple version for each. |
| Unordered set, 8+ items | Chunk by meaning into 3 or 4 groups, then one code per group | Method of loci with one room per group | Working memory holds only a few chunks (Cowan, 2001). |
| Items that share first letters badly (e.g. XQZ...) | Acrostic sentence or keyword images | Mixed | Not every list makes a pronounceable acronym. Do not force it. |
| Contrast pair (A vs B) | Concrete opposites in one scene, or a single analogy with two roles | Table with one anchor image per side | Use dual coding: a tiny two-column picture plus one sentence. |
| Typology with sub-types (2 buckets x 3 items) | Hierarchy: name the buckets with images, then the members | Loci: one room per bucket | Organised retrieval beats flat lists. |
| Long, heavy definition | Plain-language rewrite + one concrete example + one analogy | Self-explanation prompt ("in my own words...") | Do not mnemonic-code a definition you do not understand. |
| Abstract process (cycle, mechanism, model with arrows) | Analogy to a familiar process + simple diagram | Story with characters playing each part | Analogies help transfer only when the mapping is explicit (Gentner, 1983). |
| Foreign or unfamiliar term (e.g. "interlanguage", "uptake") | Keyword method (sounds-like word + image linking to meaning) | Etymology/word-parts note | Strong for concrete or semi-concrete items; weaker for abstract ones and long delays (see evidence file). |
| Names with dates or "who said what" | Person-as-image (a face or celebrity standing for the name) + one scene for the claim | Story link | Cap the date at 1 per link; do not stack many dates. |
| Numbers (cut-offs, years, percentages) | Number-shape or number-rhyme peg, or meaningful chunking (e.g. .4, .7, 1.0 = "four, seven, ten") | Link to a known number (a birthday, a shirt number) | Only memorise numbers that the student really needs. Round if the exact value is not required. |
| Criteria that map onto a known set | Direct mapping table (e.g. qualitative to quantitative equivalents) | Parallel acronym | Prior-knowledge link (schema) is the strongest anchor. |
| Decision rule ("when to use which") | If-then card plus two contrasting examples | Flow of 2 to 3 yes/no questions | Practice choosing, not just naming. |
| Very high-stakes exact wording (legal, formula) | Rote retrieval practice, spaced | Mnemonic only for the skeleton | Mnemonics do not guarantee verbatim accuracy. |

If two techniques tie, choose the one the student can build in under two minutes.

## 2. Step-by-step recipes

### Universal pre-step (30 seconds)
1. Read the item once. State in one sentence what it is and why it matters ("This lists the six ways teachers react to errors").
2. Ask: is it a list to recall, or an idea to understand? If idea, do recipe H (simple version) first.
3. Pick the technique from the decision table.

### Recipe A: Acronym
1. Write the items in the source's order.
2. Take the first letter (or a distinctive sound) of each.
3. Try to rearrange only if order is not required. If order matters, keep it.
4. Aim for a real or pronounceable word. Check that each letter reliably calls back its item.
5. Attach one 3 to 6 word gloss per letter.
6. Test: cover the items, say the code, produce the items, then the glosses.
Limit: works best for 3 to 7 items; recalls labels, not meaning.

### Recipe B: Acrostic (sentence)
1. Take the first letters in order.
2. Build a short, vivid, slightly odd sentence using words that fit the student's life.
3. Prefer concrete nouns and verbs over abstract words.
4. Test as in A. Acrostics cost more to store than acronyms, so use them only when no good acronym exists.

### Recipe C: Story / link method
1. List the items as concrete images (turn abstract terms into a thing, a person, an action; see Recipe I).
2. Chain them: item 1 does something to item 2, which does something to item 3. Use interaction, not a static list.
3. Keep one place and 1 to 3 characters.
4. Make it vivid: size, motion, humour, emotion, senses. Make it personal.
5. Replay the story twice from memory, then say the real items.
6. Keep each story under about 8 items; split longer lists into chapters.

### Recipe D: Method of loci (memory palace)
1. Choose a very familiar route (home, route to campus, a classroom) with 5 to 12 fixed stops, always in the same order.
2. Put one image per stop for each item, interacting with the location.
3. Walk the route in your head, in order, and say the items.
4. Reuse routes only after a gap, or use a different route per topic, to limit interference.
5. For students who find spatial thinking hard, pair each stop with a word label, not only a picture.
Best for 8 to 20 ordered items.

### Recipe E: Peg system
1. Learn a stable peg list once (for example number-rhyme: 1-bun, 2-shoe, 3-tree, 4-door, 5-hive, 6-sticks, 7-heaven, 8-gate, 9-wine, 10-hen; or body pegs: head, shoulders, elbows, hips, knees, feet).
2. For each item, picture an interaction with the peg image.
3. Recall by counting through the pegs.
Good when the student needs to jump to "number 4" directly (random access).

### Recipe F: Rhyme or rhythm
1. Compress the list to key words, 4 to 8 syllables per line.
2. Use rhyme, a known tune or a beat.
3. Test by saying it, then by writing the items.
Best for short lists that will be said aloud (viva, presentation).

### Recipe G: Keyword method (for unfamiliar terms)
1. Find a familiar word that sounds like the term (the acoustic keyword).
2. Picture the keyword interacting with the meaning.
3. Rehearse: term, keyword, image, meaning.
4. Use for terms that are concrete or can be made concrete. For abstract terms, attach a concrete example first.
5. Re-test after a day and a week; keyword gains can fade (see evidence).

### Recipe H: Heavy definition to simple version
1. Split the definition into its core claim, key terms and conditions.
2. Replace each abstract term with a plain word or example. Keep the exact technical term beside it.
3. Write it in one sentence, 15 to 25 words, active voice, one idea.
4. Add one concrete example from the student's life or field.
5. Check accuracy against the original: nothing added, nothing reversed, no overclaim.
6. Add a "not to be confused with" note if there is a near neighbour.
7. Student restates it in their own words, then compares.

### Recipe I: Making abstract things concrete
1. Ask: what could I see, hear, touch or do that stands for this?
2. Use a person, an object, an action, a place or a scene.
3. Use consistent images across a set (same type of thing) so the set cues itself.
4. Check that the image would cue the right term, not a neighbour.

### Recipe J: Analogy / metaphor
1. Pick a familiar source domain that has the same relational structure (not just surface looks).
2. Map explicitly: part A is X, part B is Y, the relation is Z.
3. State where the analogy breaks down.
4. Ask the student to extend or break it themselves.

### Recipe K: Chunking
1. Group items by meaning, function or time into 3 or 4 chunks.
2. Name each chunk with a short label (a word or an image).
3. Learn the chunk labels first, then the members.
4. Recall order: chunks, then members.

### Recipe L: Prior-knowledge hook
1. Ask: "What do you already know that behaves like this?" Offer two candidate hooks if the student is stuck.
2. Pick the hook the student rates as most familiar.
3. Write the link in one line ("[Term] is like [thing] because [shared structure]").
4. Check one place where the hook does not apply.

### Recipe M: Number codes
1. Round if allowed.
2. Look for pattern (steps, repeats, doubles).
3. Turn into a rhyme, a known number or a short phrase ("four, seven, ten").
4. Pair with what the number measures (small, medium, large).

## 3. Quality rules (every Memory Link must pass)

1. **Accurate.** Matches the source. Items, order and labels are correct. No new claims. If a simplification drops detail, say what is dropped. Verify against the original paper or book before it is shown as final.
2. **Vivid.** Concrete, sensory, emotional or funny. Distinctive beats ordinary. Odd images help most when they stand out from similar items in the same list; they add little when everything is bizarre.
3. **Short.** One breath. A code longer than the original list is a failure. Target under 15 words for the code, under 25 for the simple version.
4. **Personal.** Uses the student's own world (their city, hobbies, routines, apps, films, languages). Self-referenced material is remembered better. Ask the student to choose or edit, not just accept.
5. **Tied to prior knowledge.** Names the existing schema it hooks onto, so the new item sits in a network rather than floating alone.
6. **Cues the right thing.** Each element must retrieve one item and its meaning. Test: can you go from the code back to the full item without guessing?
7. **Order-safe.** If the source order matters, the code keeps it.
8. **Includes meaning.** An acronym that gives labels without understanding is incomplete; add the simple version.
9. **Testable.** Provide a one-line self-test (cover and recall).
10. **Marked as a scaffold.** Say which part is the mnemonic and which part is the source's content, so the student does not quote the mnemonic as the theory.
11. **Not offensive.** No stereotypes, no content that distracts from the item or embarrasses the student in a seminar.
12. **ADHD-friendly.** Low-effort to build (under 2 minutes), low reading load, visual where possible, one link at a time, no long lists of rules to apply the rule.

## 4. Anti-patterns

| Anti-pattern | Why it fails | Do instead |
|---|---|---|
| Acronym with forced, wrong, or missing letters | Retrieves the wrong item, or the student forgets what a letter stands for | Use a story, acrostic or loci instead |
| Mnemonic without meaning | Student can list labels but cannot explain or apply | Pair with simple version and one example |
| Over-clever code that costs more to remember than the list | Adds load | Cut it or simplify |
| Stacking several mnemonics on one item | Interference and confusion | One primary code per item |
| Giving the student a finished mnemonic and never asking for retrieval | No testing, no durable learning | Add a cover-and-recall step and spaced re-tests |
| Analogy with false mapping (misleading) | Creates misconceptions | State the mapping and its limits; verify |
| Bizarre-for-bizarre's-sake images | Distinctiveness only helps when contrasted; cheap shock fades | Vivid but relevant |
| Embedding rude, stereotyped or distressing content | Distraction, harm, rejection | Neutral or playful imagery |
| Using mnemonics for deep conceptual understanding | Mnemonics aid recall of facts, not reasoning | Use self-explanation, elaborative questions, worked examples |
| Memorising numbers, dates or lists the exam or task does not require | Wastes capacity | Triage first: what is needed for the task? |
| Changing the original wording of a technical term | Student fails to recognise it in the literature | Keep the exact term; the code is a bridge only |
| Making the student generate everything from scratch when overloaded | Executive-function cost; the student gives up | Offer 2 candidate links and let the student pick or tweak |
| One-and-done: never reviewing | Forgetting curve | Retrieve at 1 day, 1 week, 1 month (spacing) |
| Treating the mnemonic as evidence in academic writing | Not citable | Always cite the source |

## 5. ADHD-specific adaptation (summary; detail in the evidence file)

- Working memory is often a weak point (meta-analytic evidence in children and adults), so keep the number of chunks small (3 to 4), build the code in tiny steps and write it down rather than hold it in mind.
- Strategy use may not be spontaneous (Cornoldi et al., 1999, in children), so supply structure: give two candidate links, then let the student choose and personalise. This keeps the benefits of generation and self-reference with less executive load. (Design inference, not a tested protocol.)
- Interest and novelty help engagement: use humour, the student's hobbies and short, game-like retrieval rounds.
- Build routines: one 2-minute Memory Link per heavy item, then a 60-second recall check, then spaced re-checks.
- Keep the text short and visual. Prefer a one-line card plus an image over a paragraph.
- Do not assume mnemonic training is proven for adult ADHD students in particular: direct trials with this group are scarce (see evidence file), so rely on general memory science and check what works for the individual.

## 6. Output template (for agents)

```
ITEM:        [exact item, source order]
TYPE:        [ordered list | set | contrast | definition | process | number | term]
CODE:        [acronym / story / loci / peg / rhyme / keyword / analogy]
SIMPLE:      [15 to 25 word plain version, with the technical term kept]
ANCHOR:      [everyday thing the student already knows]
MAP:         [letter or image -> item -> meaning]
LIMITS:      [what the code does not capture; near neighbours]
SELF-TEST:   [one cover-and-recall instruction]
SOURCE:      [reference checked]
```

QC checklist for the ADHD QC agent: accurate to source; under length limits; one primary code; meaning included; personal/prior-knowledge hook named; self-test present; limits stated; no em dashes; no unverified citation.
